# Context: Session Data Format

## Overview

Sessions are the core data unit in CRE Analytics. Unity aggregates all data for a session locally, then submits one JSON document to the Firebase Function at session end. The Function writes it as a single Firestore document.

---

## Document Structure

```json
{
  "sessionData": {
    "metaData": {
      "projectId": "my-vr-game",
      "schemaVersion": "1.0.0",
      "sessionId": "uuid-v4",
      "platform": "quest_3",
      "startedAt": "2025-10-15T12:00:00.000Z",
      "endedAt": "2025-10-15T12:05:00.000Z"
    },
    "data": [
      {
        "columnName": "Tutorial/Started At",
        "value": "2025-10-15T10:00:00Z"
      },
      {
        "columnName": "Tutorial/Clicks/Button A",
        "value": 40
      },
      {
        "columnName": "Tutorial/Clicks/Button B",
        "value": 0
      }
    ]
  }
}
```

---

## `metaData` Fields

These are **fixed structured fields** present on every session, regardless of project:

| Field | Type | Description |
|-------|------|-------------|
| `projectId` | string | Identifies which Unity project this session belongs to. Maps to the Firestore path `projects/{projectId}/sessions/{sessionId}` |
| `schemaVersion` | string | Version of the `SessionSchema` ScriptableObject at the time the session was sent. Used to correlate sessions with the schema that describes their `data` fields |
| `sessionId` | string | UUID v4. Generated by the SDK at session start |
| `platform` | string | Platform identifier (e.g., `quest_3`, `pc`, `android`) |
| `startedAt` | ISO 8601 string | Session start timestamp |
| `endedAt` | ISO 8601 string | Session end timestamp |

Do not add more `metaData` fields without a corresponding update to this doc and to the `AnalyticsSession` runtime class.

---

## `data` Array

An array of `{ columnName, value }` pairs. Each entry corresponds to a field defined in the project's `SessionSchema` ScriptableObject.

### Key rules

- **All schema fields must be present**, even if the value is null, 0, or empty string. This is enforced by the SDK before submission. A session where half the fields are missing is invalid.
- `value` can be: `number`, `string`, `boolean`, or `null`.
- `columnName` is the string key defined in the schema — it must match exactly.

### Column name hierarchy

Column names use `/` as a hierarchy separator:
- `Tutorial/Started At`
- `Tutorial/Clicks/Button A`
- `Main Experience/Steps/Step 1/Times Repeated`

The dashboard treats these as a tree for column selection (the left part is the group, the rightmost part is the leaf). This is intentional — it makes deeply nested data readable without flattening.

There is no enforced depth limit, but keep nesting to 3–4 levels max for readability.

---

## System Fields (`Session/` Namespace)

Every session's `data` array contains a fixed set of SDK-managed fields under the `Session/` namespace. These are pre-populated by the SDK at session start and finalized at session end. They are **never** defined in the project's `SessionSchema` ScriptableObject and cannot be overwritten via `CREAnalytics.Set()`.

| Column Name | Type | Set by | Value |
|---|---|---|---|
| `Session/StartedAt` | Timestamp | `StartSession()` | `DateTime.UtcNow.ToString("o")` |
| `Session/EndedAt` | Timestamp | `EndSession()` | `DateTime.UtcNow.ToString("o")` |
| `Session/Duration` | Float | `EndSession()` | Elapsed seconds as a float |
| `Session/Platform` | String | `StartSession()` | `Application.platform.ToString()` |
| `Session/DeviceModel` | String | `StartSession()` | `SystemInfo.deviceModel` |

The Bake Analytics tool appends these five columns to every schema document uploaded to Firestore, so the dashboard always has them as queryable columns without per-project configuration.

### Reserved namespace

The `Session/` prefix (case-insensitive) is reserved. The bake tool shows a validation error and blocks the bake if any user-defined field's `columnName` starts with `Session/`. `CREAnalytics.Set()` also silently discards writes to `Session/` keys with a warning.

---

## Schema Versioning

`schemaVersion` in `metaData` is set by the "Bake Analytics" editor tool in Unity. When a developer changes the schema (adds/removes/renames fields) and bakes it, the version bumps.

Sessions submitted with different schema versions may have different `data` fields. The dashboard must handle this gracefully — columns that don't exist in a given session's schema should display as empty, not error.

Old session documents are never migrated — they remain as submitted. The `schemaVersion` field is the key for understanding what fields to expect.

---

## Firestore Path

```
projects/{projectId}/sessions/{sessionId}
```

The top-level document at `projects/{projectId}` can store project metadata (display name, created date) in future iterations. For now, the sessions subcollection is the focus.

---

## Validation (Firebase Function)

The `POST /sessions` endpoint validates:
- Full body structure via Zod (returns HTTP 400 with Zod issue details on failure)
- `projectKey` matches `projects/{projectId}.projectKey` in Firestore (HTTP 403 on mismatch, 404 if project not found)
- If a schema document exists for `projects/{projectId}/schemas/{metaData.schemaVersion}`: all `columnName` values declared in the schema are present in `sessionData.data` (HTTP 422 with list of missing column names if not)

If no schema exists for the submitted `schemaVersion`, column validation is skipped (backward compat for the transition period).

---

## Schema Storage

When Unity bakes a schema, the `bakeSchema` function writes a document to `projects/{projectId}/schemas/{schemaVersion}`:

```ts
{
  columns: Array<{
    columnName: string;
    dataType?: 'string' | 'number' | 'boolean' | null;
  }>;
  bakedAt: string;  // ISO 8601
}
```

The `dataType` field is optional and reserved for future display hints in the dashboard table (e.g., formatting numbers vs. timestamps). It is not used for validation. Unity may omit it — the function stores `null` if absent.
