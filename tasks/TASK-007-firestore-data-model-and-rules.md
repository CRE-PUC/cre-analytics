## Description

Define the `Project` TypeScript interface and write real Firestore security rules. Currently `firestore.rules` blocks all reads and writes (`allow read, write: if false`), and the project document structure is not typed anywhere in the codebase.

The project document lives at `projects/{projectId}` in Firestore. The document ID (`projectId`) is a UUID generated by the backoffice at creation time and is also what the Unity SDK sends in `metaData.projectId`.

## Acceptance Criteria

- [ ] `functions/src/types.ts` exports a `Project` interface matching the shape below
- [ ] `firestore.rules` allows authenticated backoffice users (any non-null `request.auth`) to read and write `projects/{projectId}` documents
- [ ] `firestore.rules` allows authenticated users to read `projects/{projectId}/sessions/{sessionId}` documents
- [ ] `firestore.rules` blocks direct client writes to sessions (the `submitSession` Function uses the admin SDK, which bypasses these rules)
- [ ] All other Firestore paths remain blocked by the default deny-all

## Relevant Data

**Add to `functions/src/types.ts`:**
```ts
export interface Project {
  projectName: string;
  projectDescription: string;
  projectKey: string;   // secret for Unity SDK auth — generated as crypto.randomUUID() at creation
  createdAt: string;    // ISO 8601 timestamp
  updatedAt: string;    // ISO 8601 timestamp
}
// Firestore document ID = projectId (UUID, generated by backoffice at creation time)
```

**Target `firestore.rules` (replace the existing file entirely):**
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /projects/{projectId} {
      allow read, write: if request.auth != null;

      match /sessions/{sessionId} {
        allow read: if request.auth != null;
        allow write: if false;
      }
    }
  }
}
```

Note on `allow write: if false` for sessions: Firebase Functions using the admin SDK bypass Firestore security rules entirely. The `submitSession` function will continue to write sessions without issue. This rule only prevents a logged-in backoffice user from writing sessions directly via the client SDK.
